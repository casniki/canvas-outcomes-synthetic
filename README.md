# canvas-outcomes-synthetic

A Power BI project (PBIP) for Canvas learning-outcome assessment at Loma Linda University, populated with **synthetic data** so the model, measures and four-page report can be shared and demonstrated.

> **Personal project.** This is not an official Loma Linda University product. LLU has not reviewed or endorsed it, and it is not supported by LLU. Loma Linda University's name appears only because the institutional metadata (school, department, program and outcome names) comes from its Canvas instance.

## What is real and what is not

- **All data is synthetic.** Every student, name, SIS ID, login ID, course, enrollment, section, assignment, rubric, score and date was generated by `tools/make_synthetic.py` with a fixed random seed. No student, enrollment, instructor, course-name or outcome-result record from LLU's Canvas instance is included.
- **Institutional metadata is real.** School, department and program names, and outcome titles, types and groups, are real LLU institutional metadata, extracted from the production model by `tools/extract_metadata.ps1`. The extract leaves two kinds of free text out:
  - Course names are replaced with generic names such as "Course 312".
  - Faculty-written course-outcome titles are replaced with "Course Outcome *n*".
- **Figures are invented.** Rates, counts and trends in the report come from the generator and describe nothing real. In particular:
  - the programs on the watchlist were chosen at random;
  - program mastery rates were drawn at random.

## Mirror this build

You need Power BI Desktop for Windows. A recent release is required, because the project uses the PBIP and PBIR formats.

1. **Get the files.** Clone or download the repository, for example to `C:\code\canvas-outcomes-synthetic`.
2. **Open the project.** Open `canvas-outcomes-synthetic.pbip` in Power BI Desktop.
3. **Point it at the data.**
   - The `DataFolder` parameter is set to `C:\code\canvas-outcomes-synthetic\data\`. If you put the project somewhere else, change it under **Home → Transform data → Edit parameters**.
   - The value must end with a backslash.
4. **Load the data.** Click **Home → Refresh**. Every table loads from the CSVs in `data/`, which takes a minute or two.
5. **Save.** The report's four pages now show the figures in `screenshots/`.

**Optional tools:**
- **Rebuild the report pages** from code with `node tools\build_report.js 4` (Node.js 18 or later). Then reopen the project, or reload it in Desktop.
- **Regenerate the data** with `python -I tools\make_synthetic.py` (Python 3.10 or later, standard library only). It writes the same files every time.
- **Adapt it to your own Canvas data:** replace the CSVs in `data/` with your own extract, using the same file and column names, then refresh. Your extract will contain student records, so keep it out of any public repository.

## Layout

| Path | Contents |
|---|---|
| `canvas-outcomes-synthetic.pbip` | Open this in Power BI Desktop. |
| `canvas-outcomes-synthetic.SemanticModel/` | TMDL model. Each table reads `data/<table>.csv` through the `DataFolder` parameter. |
| `canvas-outcomes-synthetic.Report/` | PBIR report, built by `tools/build_report.js`. |
| `metadata/` | Institutional metadata extract (input to the generator). |
| `data/` | Generated CSVs, one per model table, with the model's source column names. |
| `screenshots/` | One PNG per report page. |
| `tools/` | Extract, generate, point-at-CSV and report-build scripts. |

## Regenerate

1. `powershell -ExecutionPolicy Bypass -File tools\extract_metadata.ps1 -Port <port>`
   - Needs the production model open in Power BI Desktop and the ADOMD client that ships with SSMS.
   - Only needed when the institutional metadata changes.
2. `python -I tools\make_synthetic.py`
   - Writes `data\*.csv`.
   - Reruns produce identical files.
3. `python -I tools\csv_sources.py`
   - Only needed after copying TMDL from the production model.
   - Replaces each table's source with its CSV.
4. Open the `.pbip`, set the **DataFolder** parameter if the project moved, refresh, then save.
5. `node tools\build_report.js 4`
   - Rebuilds the report pages.

## Generator design

- **Population:**
  - About 3,000 students.
  - 400 courses spread across the real departments, plus 5 test courses whose results the measures exclude.
  - About 60,000 outcome results from 2022-07-01 to 2026-10-31.
- **Program mastery:**
  - Program mastery (LLU standard) varies between programs from about 70% to 97%.
  - Most programs have a Not Met rate of 3–15%.
  - Three programs with 20 or more scored results have no Not Met results, so the watchlist page has entries.
- **Core values:** 1,500 core-value results cover all seven values in every school for 2025-26 and 2026-27.
- **Mastery scales and the Canvas flag:**
  - Most outcomes use a 4-point scale with mastery at 3, which matches the 75% LLU standard.
  - About 10% use a 5-point scale with mastery at 3.
  - Is Mastery follows the scale, so the Canvas-flag cross-check differs slightly from the LLU rate.
- **Excluded rows:** about 1% hidden results, a few score outliers and the test-course results are included, so the exclusions can be seen working.
- **Programs and outcome types:** every outcome keeps its production Outcome Type and Program.
  - For a few Dental Hygiene PLOs, the rule that names the program is a department rule instead of the cohort-shell rule, because synthetic course names are generic.
