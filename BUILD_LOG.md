# Build log — canvas-outcomes-synthetic

Full build history is in the private production repository, canvas-outcomes.

## Design decisions carried over from production

### Source and dates

- The model is a star schema around **Outcome Results**, the Canvas learning-outcome results. It has dimensions for:
  - learning outcome and outcome group;
  - course, with term and account (school and department);
  - user;
  - date, using academic years that run July to June;
  - assignment and rubric association.
- Results are kept from **2022-07-01** onward (the `Results Start Date` parameter).
- **Dates are UTC.** Canvas stores timestamps in UTC, and the assessed date is the UTC calendar date. A result recorded late in the evening Pacific time therefore falls on the next day.
- Corrupt or out-of-range scores are blanked and flagged as score outliers, so they drop out of every mastery measure.

### Outcome types

Each outcome is classified from its title and group path. The first rule that matches wins:

1. **Core Value:** the outcome sits under the LLU Values Alignment group.
2. **Institutional Outcome:** university SLO groups, `SLO-` titles, or ILO / institutional-learning-outcome wording.
3. **PLO:** PLO / PLOs / PLO*n* or "program learning outcome" wording.
4. **Accreditation Standard:** CODA, CAPE or NAPLEX references.
5. **Course Outcome:** everything else.

### Program (PLOs only)

Rules are applied in this order; the first match wins:

1. **Catalog path:** the outcome sits under *LLU Program Learning Outcomes > School > Program*.
2. **School path:** an account-level group *School of … > Program > …*.
3. **Title code:** a Program Code Map code appears as a whole word next to PLO in the title or group path (for example `PLO DDS 9`, `MHA PLO 3`).
4. **Cohort shell:** the owning course is a cohort shell named `~{code} Class of YYYY`.
5. **Owning-course department:** the owning course's Canvas department, excluding non-program accounts and school-level catch-alls.
6. **Recorded-course cohort shell / Recorded-course department:** the same course rules, applied to the non-test course where most of the outcome's results were recorded.
7. **Unmapped:** no rule matched.

Department rules translate Canvas department names to register program names through the Program Code Map. Each map row has a Code Type of either *Code* or *Department alias*. Program names follow the LLU program register ("Program — Degree"). One program in the map is closed and has no results.

### Mastery and exclusions

- **Mastery standard:** a scored result is mastered when Score / Points Possible **≥ 0.75**, the LLU standard. Pct at Mastery (LLU) is the reporting measure.
- **Canvas-flag cross-check:** Pct at Mastery (Canvas flag) uses each outcome's own Canvas mastery threshold, with the same denominator.
- **Not Met Rate** = 1 − Pct at Mastery (LLU).
- **Exclusions:** every mastery measure excludes:
  - hidden results (Is Hidden);
  - results in test courses: course names that contain the whole word TEST, TESTS or OEE;
  - results without a score or with Points Possible ≤ 0.
- **Watchlist:** a program is on the watchlist when it has at least 20 scored PLO results and a 0% Not Met rate. Every scored result at mastery usually means the rubric is not separating performance levels.

### Report

- Four pages:
  1. Institution Overview;
  2. Program Drill-Down, the drillthrough target for School;
  3. Core Values;
  4. Assessment Quality Watchlist.
- 16:9 layout.
- Navy, ice-blue and gold theme, with Cambria headings and Calibri body text.
- Every page has a "Data as of" label taken from the latest assessed date.
- No visual uses user names, SIS IDs, login IDs or instructor fields. Course Name is not shown on any page.
- Pages are generated by `tools/build_report.js`.

## 2026-11-13 — Synthetic project created

- **Copied from the production PBIP:**
  - the semantic model and report;
  - the report generator.
  - The production data cache, local settings and history were not copied.
- **Data sources:**
  - Every imported table now reads `data/<table>.csv` through a `DataFolder` parameter. This was done by `tools/csv_sources.py`, with column names and data types unchanged.
  - The production warehouse connection and its parameters were removed.
  - Date and Program Code Map are generated in Power Query and keep their definitions.
- **Metadata extract:** `tools/extract_metadata.ps1` reads only institutional metadata:
  - accounts (school and department);
  - outcome titles, types and groups;
  - programs;
  - the Program Code Map.
  - Canvas IDs are renumbered.
  - Course-name root groups are replaced by a placeholder.
  - Group names that carry course codes or personal names are replaced.
  - Course-outcome titles are not extracted.
- **Data:** `tools/make_synthetic.py` generates every user, course, enrollment and result with a fixed seed. Generator parameters are in the script and the README.
- **Checks after refresh:**
  - Every outcome's Outcome Type and Program in the synthetic model matches production.
  - Cohort-shell programs resolve through the department rules instead, because synthetic course names are generic.
  - All four pages validate and render.

## 2026-11-13 — Slicer selection color

- List slicers now fill the selected checkbox in gold. The default near-black fill could not be seen on the navy filter rail. Page 1 screenshot updated.

## 2026-11-13 — Larger fonts

- **Text sizes:** text across the report is larger, and every visual stays within its bounds.
  - Visual titles are 15 pt.
  - KPI values are 32 pt.
  - Slicers are 13 pt.
  - Chart labels and axes are 12–13 pt.
  - Tables are 12 pt.
  - The page title is 26 pt.
- **Layout:**
  - The KPI row is 112 px tall, and the main visuals start below it.
  - Tables and matrices use fixed column widths, so every column stays visible; long text wraps.
  - Page 4's KPI cards are narrower, which gives the explainer more room.
  - On page 3, the bar chart is narrower and the core-value matrix wider, so school names wrap at word breaks.
  - The page 2 back button now reads "Back to Overview".
- All four screenshots are updated.

## 2026-11-13 — Publishing prep

- **Student names:** the generator's surname list is now invented surnames only. No generated name can match a real person.
  - The list is the same length, so every other generated table and every figure in the report is unchanged.
- **Code comments:** example outcome IDs, course codes and CRNs in the code comments were replaced with made-up placeholders.
- **Name check:** before publishing, every tracked file was checked against the institution's user roster.
  - The roster was read in memory only. Nothing from it was written to disk.
  - Code, documentation, metadata and the model matched no real person's name; the only hits were ordinary words and place names.
  - No generated student name matches a real user.
